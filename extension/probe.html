Scene metadata — the 2026-08-27 questions

Scene metadata is ~500x the room's and dies with the scene, so it is the candidate home for NPC sheets. Three things have to be true before anything moves there. Open a scene first; all three clean up after themselves.

Scene stamp is the one that matters, and it takes two presses in two scenes: press it here, then duplicate this scene in Owlbear, open the copy, and press it again. The same nonce in the copy means a prepped encounter travels with its map; no stamp means every prepped map needs its own import. Safe cap finds the largest write that also clears again, which is the number "Scene cap" above does not give — it found no ceiling below 8 MB and then could not delete the blob. Write timing does ten 40 kB writes (about thirty villains) to see whether the rate limiter shows up.

Capacity

Answered in round 3 — you probably want "Storage report" instead. Room = 16,384 chars whole-document; item 512 kB each; scene >= 8 MB but chunked. These fill the store with incompressible filler to measure a byte budget, so they trip the rate limiter and leave large values behind. Item and scene need a token selected / a scene open.

Local-item attachment

Select a token. Attaches a non-synced marker, moves the token 250 units, and checks whether the marker followed. Decides whether status badges can be local — which would avoid leader election and scene clutter entirely. Puts the token back afterwards.

Token geometry

Select a token and dump what OBR actually reports about it — position, scale, image size, grid dpi and offset — plus the centre and height the extension computes from those. Badge placement depends entirely on these numbers.

Grid

What this scene says about itself. A scale of "5ft" with a sane dpi means ranges can be computed; a blank or default scale on an imported map means they cannot, and the Table pane will need its own multiplier.

Range

Select exactly two tokens. Computes the separation three ways and asks OBR for its own answer, then says which unit that answer is in — pixels, grid cells or scaled units. Ranges in the app are 60x wrong if this is guessed. Rerun at several separations, including a pure diagonal, which is what distinguishes Chebyshev from Euclidean.

Scale multiplier (writes to the scene, then puts it back)

On a scene whose scale multiplier is 1 — "1m", "1 square" — cells and scaled units are the same number, so measuring alone cannot tell which one OBR returns. This changes the scale to a known multiplier, re-measures the same two tokens, and restores the original. It is the only probe that writes to the scene: the original scale is logged first, and restored even if the test fails.
